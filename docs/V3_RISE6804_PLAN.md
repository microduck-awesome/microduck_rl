# V3 起身 6804 迁移与训练计划

## 来源和目标

从 `publish/v2-rise6804-training-20261031` 的 `67120c2fc9c5f4be8323ce04588ab18c9a643e45` 建立独立分支，迁移 assembly `46a1b2c1d371def5775d33e67424755f253e9881` 的结构、完整起身碰撞、质量惯量与第二组 HOME。训练使用物理 GPU 0；单卡与原双卡全局批量不同，记录为新的 V3 实验，不声称逐轨迹复现。保留 61 输入、14 动作、独立嘴和 SC0090 训练契约。原 V2 源和检查点保持原样。

## 实施与准入

1. 固定 assembly 资产和来源哈希；对编译后全部 body、joint、惯量、有效碰撞、mesh、HOME 和 site 进行逐项对照。分析 15 关节顺序与轴方向，明确 HOME 绝对坐标和相对动作/观测；检查所有限位和动作空间。
2. 审计起身初态、姿态奖励、头部命令、站立高度、碰撞选择器及 reset 是否硬编码 V2；采用 V3 HOME，依实际物理确定需要迁移的量。保留原训练配方，不擅自改写奖励及课程。若现有 V2 坐姿或起身姿态在 V3 穿透或不可达，先报告并分析，不能靠忽略碰撞通过。
3. CPU 资产一致性和配置检查，HOME 实际电机保持、七类重置的穿透和有限性检查；64 环境 5 更新 GPU smoke 后检查 observation/action、奖励、NaN、导出。再进行实际批量的有界预检；失败时保留证据并修复，不能进入正式训练。
4. 以源分支的训练阶段和检查点含义为基础，在 GPU 0 执行有界正式训练，记录种子、批量、阶段、环境版本、日志、优化器和 RNG。每阶段按行为评测决定继续，不能仅凭 reward 认定完成。单卡训练中不借用另一 rank 的 RNG。
5. 使用七初态恢复及头控协议评估，检查全部 14 关节限位、身体和头部接触、无效数值；导出包含 normalizer 的 61→14 ONNX，并对原生网络做数值比对。记录 V3 与原 V2 物理和协议差异，不声称实机资格。提交并核验源码、资产和结果身份。

以上是执行计划，不是已通过的验收。需在迁移检查后具体锁定站立/坐姿可行区、训练阶段起点和正式预算。
