# SC0090 碎步与头部振动诊断

用户指出 Pages 视频的行走是碎步、头部振动明显，缺少自然的鸭子步态。
Pages 使用物理修订 2 下的 6400 模型。速度跟踪通过不能替代这项动作质量要求。

## 同条件复测

使用与 Pages 相同的 CPU MuJoCo + BAM、12 V、80 rpm、50 Hz 策略执行及观测延迟，
零头部和身体指令，无随机扰动。对比 Pages 6400 与关闭熵奖励续训后的 6600，
每个指令运行 12 秒，统计第 2–12 秒。两者在四种前进指令下均未跌倒。

| 0.10 m/s 指令 | Pages 6400 | 转身续训 6600 |
| --- | ---: | ---: |
| 实际前进速度 | 0.0994 m/s | 0.0983 m/s |
| 两脚合计落脚频率 | 10.8 次/秒 | 10.7 次/秒 |
| 同一只脚两次落地间前进距离，中位数 | 18.2 mm | 18.2 mm |
| 腾空时长，中位数 | 0.08 秒 | 0.08 秒 |
| 头部世界角速度 RMS | 3.26 rad/s | 3.02 rad/s |
| 头部角速度主频 | 5.5 Hz | 5.4 Hz |

按平均速度除以两脚合计落脚频率，每次落脚只前进约 9 mm；这与同脚完整跨步约
18 mm 是不同定义。碎步并非视频倍速造成：Pages 播放为 1×。
关闭熵奖励改善了转身，但此处头部角速度只减少约 7%，碎步基本没有改善。

在 0.08 m/s 时，6400 约 11.5 次落脚/秒；0.30 m/s 时约 8.0 次/秒。
低速主要通过缩短步幅实现，步频反而更高。头部摆动的主频接近单脚步态循环频率，
支持头部动作与平衡策略耦合的解释，不能单凭频率认定唯一原因。

落脚由足底法向接触力识别，需前后分别至少两个采样点的腾空和接触以排除一次采样的抖动。
同脚跨步沿前一次落地时的水平朝向投影，排除统计窗口两端不完整的腾空。
这些是标称模拟测量，尚不代表随机场景或实机。

## 配置中的不足

- 为解决低速难学，SC0090 配置把腾空奖励窗口下限从 0.125 秒降至 0.075 秒，
  权重从 3 降至 1.5，并随速度缩放。在 0.10 m/s 时，单脚处于奖励窗口时的系数
  只有 0.75。这给短促步态留下空间，但尚未通过独立对照证明它是唯一成因。
- 头部跟踪与 1 秒误差均值主要约束姿态和下垂，不能保证头部在世界坐标中稳定。
  当前全关节动作差惩罚较轻；转身续训日志中这一项约为 −0.043，而头部跟踪奖励
  约为 +1.86。两者衡量对象不同，不能只比较权重或把头部跟踪达标当成不抖。
- V4 将增强平滑安排在抗扰、身体姿态之后。即使进入该阶段，全关节动作差与力矩差
  也不能单独保证更长步幅或自然摆动。

## 下一轮步态试验的约束

先把较长、完整的摆腿和头部稳定作为独立试验目标。可对照恢复原版的 0.125 秒
腾空下限，以及逐步增加头部运动的代价；每次只改变一个因素，先核对奖励贡献。
0.125 秒来自原版已使用的设置，并非新的“鸭子标准”。优先减少同频快速甩头，保留
低频身体侧摆和转向所需动作，不预设僵硬的固定姿势。

头部相关惩罚需保留头部指令跟踪、转身和起身自由度；原版已有收紧头部瞬时姿态误差后
停止迈步的失败记录。起身专家使用独立任务。步态候选应同时复核速度、启停、左右转身、
不跌倒以及上述步幅/步频/头部指标，再用相同速度、视角和 1× 播放视频判断观感。
转身续训尚未解决碎步；下面的首轮步态对照也未显示碎步改善。

## 第一轮专项对照

两组均从转身续训的 `model_6800.pt` 开始（SHA-256
`6e6b28f4c93f3fda796b4a4f9af4f22162a6c8dc5a870ff7f9677aa462ce6418`），保留优化器、
归一化和累计计数，继续使用熵系数 0。控制组腾空下限 0.075 秒，实验组 0.125 秒；
其它奖励、物理、指令分布、种子和环境数量保持相同。起点的左右转保留场景为
242/256、216/256；这只是已有技能基线，并未通过全部正式晋级条件。

每组先做 64 环境 × 5 次更新检查，核对实际配置、优化器步数、归一化计数、有限数值
和归一化 ONNX 导出。通过后，各做 8192 环境 × 200 次新增更新，对应已有的一个
完整评估间隔。这个预算用于取得第一轮对照结果，不表示 200 次更新足以学会自然步态。
两项续训完成末次评估并释放 GPU 后，监督进程于北京时间 19:54 启动正式试验，
20:04 完成训练和两组 CPU 步态复测。

试验使用冻结的物理修订 2 代码，现有 CLI 即可表达差异，无需改变 PPO 或摩擦计算。
实验组必须带以下覆盖参数（控制组将 0.125 换为 0.075）：

```bash
--env.rewards.air-time.params.threshold-min 0.125 \
--agent.algorithm.entropy-coef 0
```

再次续训该实验组时也要保留这些覆盖参数；默认 V4 配置仍为 0.075 秒和熵系数 0.01。
末次完整技能评估后，监督进程分别运行 `diagnose_gait.py`，复核步频、同脚跨步距离、
头部世界角速度及跌倒。第一轮只检验腾空下限的影响，稳头奖励留待独立对照。
运行状态在 `logs/sc0090_setup/gait_trial.json`，由 `active_training.json` 索引。

### 结果：不采用本轮实验配置作为步态改进

两组均正常完成 200 次新增更新，优化器和归一化计数核对通过，每次日志的 NaN 终止率
均为零，动作标准差仍为正。默认演示模型及 Pages 视频未替换。

| 0.10 m/s 指令，第 2–12 秒 | 控制组 0.075 秒 | 实验组 0.125 秒 |
| --- | ---: | ---: |
| 实测前进速度 | 0.0992 m/s | 0.0981 m/s |
| 两脚合计落脚频率 | 10.7 次/秒 | 11.0 次/秒 |
| 同脚跨步距离中位数 | 18.3 mm | 17.8 mm |
| 腾空时长中位数 | 0.08 秒 | 0.08 秒 |
| 头部世界角速度 RMS | 2.82 rad/s | 2.74 rad/s |
| 头部角速度主频 | 5.4 Hz | 5.6 Hz |

实验组此处落脚频率上升约 2.8%，跨步距离缩短约 2.9%，头部角速度仅下降约 2.9%。
四种前进速度的标称 CPU 回放均未跌倒，但均未出现希望的步频降低或跨步增长。
两组各 14 × 2 个固定标称技能场景全部通过；随机场景仍未通过完整晋级门槛。
例如右转保留场景从控制组 218/256 提高到实验组 237/256，但右曲线从 245/256
降至 231/256，不能据此宣布技能全面改善。

0.125 秒是腾空奖励的窗口下限，不是强制动作时长。在这次续训中，实际腾空仍短于
该下限，实验组末次日志的加权腾空奖励约 0.0095，控制组约 0.1846。观察结果支持
“提高门槛使当前步态很少拿到该项奖励，却未在本轮学出更长摆腿”的解释。
这只是同一训练种子下的一次短对照，不能证明较长摆腿不可行，也不是完整恢复原版奖励配置。
下一轮应检查能否在当前步态到目标步态之间提供有效的奖励反馈，稳头目标仍需独立验证。
后续[文献与开源源码调研](sc0090-gait-research.md)确定了头颈独立平滑、适配本机参考步态的
实施顺序，并列出相位观测与既有 checkpoint 的兼容边界。
新增[官方模型量化对照](sc0090-official-gait-comparison.md)：在实际约 0.11 m/s 时，Pages
6400 的落脚频率和头部世界角速度 RMS 分别约为官方新版模型的 2.29 倍和 2.37 倍。
该结论来自固定参数 CPU 仿真；官方模型使用其训练依赖锁定的 XL330 参数。

完整对照记录位于 `logs/sc0090_setup/gait_trial_cu946t4z/comparison.json`。
控制组 checkpoint SHA-256 为 `d45d1c471eacfed56345bfa48922506352de7f311545f88fd91455b590938177`，
实验组为 `f37d595b7146735890feb1a7f7258288a5031a5009a32c55ac300d01e7095525`。
