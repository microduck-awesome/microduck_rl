## 转身诊断

6400 的完整验收中，左右转身分别只有 1/256、2/256 达到速度跟踪标准。
这是跟踪达标数，并非未倒地数量。另一次固定指令扫描使用种子 2026091507，
每个指令 32 个样本，保留域随机化和观测噪声、关闭外部推扰，取第 2–8 秒均值：

| ±0.6 rad/s 指令 | 左转实测 | 右转实测 |
| --- | ---: | ---: |
| 确定性策略 | +0.332 rad/s | −0.326 rad/s |
| 按训练分布采样动作 | +0.530 rad/s | −0.538 rad/s |

同一确定性策略在 ±0.8 指令下达到约 +0.558/−0.541 rad/s，±1.0 下达到
+0.792/−0.755 rad/s。模型可以产生更快的转身，因此不足不能仅归因于电机转不动。
控制边界采样中部分关节峰值接近 80 rpm，硬件约束仍可能影响动作；这些结果不是实机测量。

静止初态的右转尤其依赖采样噪声。当前证据支持“策略利用随机抖动，而确定性执行减慢”这一解释。
同一编译模型、初态、参数和观测时序下，归一化 actor 与 ONNX 最大差异为 4.17e−7；
CPU/GPU 的闭环转向仍存在明显差异，不能用这个输出误差声称闭环轨迹一致。

扫描脚本可以重跑确定性与随机采样两种条件：

```bash
MUJOCO_GL=egl uv run python scripts/diagnose_sc0090_walk.py \
  --checkpoint /path/to/model_6400.pt --output-dir logs/turn_probe
MUJOCO_GL=egl uv run python scripts/diagnose_sc0090_walk.py \
  --checkpoint /path/to/model_6400.pt --output-dir logs/turn_probe --stochastic
```

脚本保留失败数；发生过终止的样本不计入后续重置轨迹的速度均值。电机统计按 50 Hz
控制边界采样。扫描用于诊断，完整阶段验收仍由 `program_evaluation` 执行。

## 等预算对照

两组各新增 200 次 PPO 更新，等于现有的一个评估间隔，从同一 6400、相同种子开始，
每组 8192 环境，最终在 6600 做完整验收。唯一有意改变的配置是熵奖励系数：
对照组 0.01，实验组 0。

熵系数为零不等于确定性训练：动作仍按策略当前的高斯分布采样，PPO 的概率、比值与梯度
计算保持原实现；标准差由学习更新，没有强行改写动作或直接压缩 checkpoint 中的标准差。
两个配置均先通过 64 环境 × 5 更新的续训检查，计数增量和阶段状态得到核对。

完整评估结果如下，分母为两个种子合计的 256 个随机化保留场景：

| 6600 对照结果 | 原熵系数 0.01 | 熵系数 0 |
| --- | ---: | ---: |
| 左转达标 | 5/256 | 206/256 |
| 右转达标 | 0/256 | 184/256 |
| 平均左转速度 | +0.339 rad/s | +0.490 rad/s |
| 平均右转速度 | −0.301 rad/s | −0.478 rad/s |
| 0.08 m/s 前进达标 | 249/256 | 249/256 |
| 平均动作标准差 | 0.0441 rad | 0.0197 rad |

实验组在这两个种子的全部固定标称场景通过。新种子 2026091510/1511 复核中，左右转为
176/256、187/256，0.08 前进 252/256，启动 253/256、停止 256/256；标称右转仍有一次未达标。
因此选择实验组继续训练，但仍不满足每个场景、每个种子的正式晋级门槛。
其它行走指标多数改善，也有小幅波动：例如右侧移保留达标从 243/256 变为 239/256，
0.10 m/s 前进从 255/256 变为 252/256；后续继续保留这些回归检查。

CPU 模拟器的固定场景复核中，±0.6 指令实测 +0.659/−0.545 rad/s，0.08 前进实测
0.0767 m/s；六种指令均未触发跌倒。CPU/GPU 仍有差异，这些是单次标称回放。
用户随后指出 Pages 的碎步与头部振动；[步态复测](sc0090-gait-quality.md)确认
6600 的转身改进尚未解决这些动作质量问题。

后续从实验组 6600 再新增 400 次更新，对应 6800、7000 两个评估点。继续显式使用
`--agent.algorithm.entropy-coef 0`。关闭熵奖励仅作为成熟策略的续训设置，默认从零训练配置
仍保留探索奖励；本次没有改动 PPO 概率、梯度或电机数值实现。
6800 评估中左右转保留场景提升到 242/256、216/256，仍未通过全部晋级条件。

## 起身与低速

起身 6400 已有 `push_10` 阶段的一次通过记录。续训新增 800 次更新，覆盖四个现有
评估间隔；保留这次通过记录，按连续通过和最短阶段经验要求晋级，预算耗尽不代表全部阶段完成。
训练从冻结的代码快照运行，行走诊断及本地演示修改不会改变正在运行的起身环境。
6600 的评估再次通过 `push_10`：保留与挑战各 1791/1792，起身时间 P95 约 1.4 秒，
已按连续通过规则进入 `push_15`。更强扰动、身体姿态和平滑阶段仍需逐级验收。
6800 首次通过 `push_15`，保留 1789/1792、挑战 1787/1792，起身时间 P95 约
1.44 秒。7000 再次通过，保留 1792/1792、挑战 1791/1792，P95 约 1.40 秒，
按连续通过规则进入 `push_20`。

纯行走训练继续使用 0.08 m/s 的最低目标，0.03 m/s 作为诊断。自由探索的自动行走也
优先使用至少 0.08 m/s，低速段为 0.08 m/s；用户设置更低的滑块上限时遵守该上限。
手动指令保留原范围。这是当前策略的工作范围选择，不是实测舵机下限。
