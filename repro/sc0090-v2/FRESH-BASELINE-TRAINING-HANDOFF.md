# 全新基线训练交接：真实后背碰撞与后仰稳定性

更新日期：2026-10-21。本文记录本轮讨论的最终决策，供训练同事直接执行。

**采用一条正式训练路线：从随机初始化开始，借鉴 3762 基线的成功经验，修正后背碰撞，强化小幅后仰时的平衡恢复。不续训旧权重，不引入 P04 特有的训练链路，不安排候选模型、路线比较或消融实验。以实际机器人表现决定是否完成任务。**

本文覆盖此前交接中“基线→量化适应→完整 P04 续训”的建议，也覆盖将新的反馈/延迟近似直接作为训练默认值的建议。历史训练源码、权重、发布清单与结果保留，不改写历史身份。

## 1. 已知实测结论与尚未解决的问题

当前设备为 D747A9，15 个 SC0090 舵机，策略控制其中 14 个关节，嘴巴独立。

- `rise_baseline_paired3762` 是当前已测试候选中操作者认为实物效果最好的模型。
- 基线经 P04 续训的 4466 被明确评价为“更差”；P04 1856 实物效果也较差。不得因为某套程序行为理论上更接近真机，就默认采用它。
- 基线 3762 已从伏卧、有防倒保护的状态连续运行 **900.000776 秒**，操作者反馈“能起身并基本站稳”。
- 该轮完成 45000 次观测/推理和 44999 次目标提交；末帧结果晚于授权截止 6.539 ms，未提交。没有重启、固件故障或策略缺反馈，15 台舵机目标回读无不匹配。
- 电脑状态读取超时 1 次，未中断 P4 本地运行；正常到期后三路卸力。采样到的舵机最高温度为 68°C。
- **仍有明显方向不对称：前倾时反应灵敏；轻微后仰时保持能力差，外观上缺乏相应纠正，往往倒下后才响应。** 这是操作者观察，不能直接等同于已经证明 MLP 原始输出不变。

证据：[15 分钟实测记录](evidence/hardware/baseline3762-15min-20261021.json)。长时间运行完成证明该轮运行链路持续工作，不代表后向抗扰问题已经解决，也不是所有起始姿态的成功率统计。

## 2. 全新训练的起点与明确排除项

训练配方参考 `rise_baseline_paired3762` 的[冻结来源](snapshots/rise_baseline_paired3762.json)和[训练参数](recipes.json)，不要从当前混合了其他任务改动的环境入口猜测它的配置。

原基线任务：`Mjlab-StandUp-Flat-MicroDuck-V2-PairedError-Baseline`。

| 项目 | 执行要求 |
|---|---|
| 初始化 | actor、critic 随机初始化；优化器、训练计数、课程状态和归一化统计重新初始化 |
| 模型继承 | 不加载 3762、1856 或 4466 权重，不 resume，也不 warm start |
| 训练配方 | 借鉴基线的网络、PPO、奖励结构、课程与随机化；保留可追溯的新任务配置 |
| 已知网络/PPO参考 | actor 为 512/256/128、ELU；原记录 N=8192、T=24、E=5、M=4，完整设置以 recipes 为准 |
| 观测与动作 | 保留基线语义、顺序与单位；actor 为 61D，策略动作 14D，输出为相对 HOME 的目标弧度，非相对当前角度的增量 |
| P04 特有改动 | 不默认引入原生 count 量化闭环、P04 S0/O0 观测前端、有效性故障终止规则、残差处理及额外延迟链路 |
| 模型路线 | 只实现并训练本文确定的一条路线，不建立候选矩阵或消融分支 |

基线名称包含 PairedError，其已用过的配对反馈误差随机化也是成功配方的一部分。不能仅因其误差数据与 P04 研究有关，就把基线原有随机化删掉；这里排除的是**相对基线新增的 P04 实现差异**。保持基线的连续动作训练思路，不移植整套 P04 观测和执行链。

冻结配方中某些旧文字要求后续保留 P04 前端修复，那是历史迁移路线的记录；本任务不沿用该迁移路线。真正的导出顺序、单位、模型身份或数值正确性问题仍应修正，不能以保留基线为由引入接口错误。

## 3. 官方、基线训练与当前真机各自如何对齐

“对齐官方”不表示把官方最新主线和 P04 的所有机制重新拼成一套环境。优先级为：**本轮明确要求 → 基线成功经验与真机事实 → 官方固定版本作为参考**。

### 3.1 保留的训练基准

以 3762 实际冻结训练实现为参考，包括原有 BAM、随机化、奖励和时序语义。新训练不自动加入本轮讨论过的额外量化、滤波或传感器仿真机制。

此前提出的位置 5 ms、速度 20 ms、IMU 0/20 ms、发送 10/15/20/25 ms，是尚未验证其训练收益的近似方案，**本次不将其直接设为训练默认值，也不围绕它安排候选实验**。基线已有的延迟与随机化按其实际实现保留；具体背景见[延迟说明](../../docs/baseline_sim2real_delays.md)。

### 3.2 保留的已验证部署行为

此次效果较好的实机运行使用以下部署设置，训练同事必须知晓并在部署评估中保持，不能为追求理论一致擅自改掉：

- P4 策略 50 Hz；当前舵机反馈 100 Hz，IMU 120 Hz。
- HOME 为 V2 CAD 坐标中的全零角度，当前模型 action scale 为 1。61D 顺序与 14D 动作顺序不能改变；ONNX 内含归一化时，运行端不得再次归一化。
- 头部目标 EMA 系数 0.5，腿部 0.7。
- 11.1 V 参考电压补偿已开启；策略电压滤波为 1 Hz、EMA α=0.1，倍率为 `11.1 / clamp(V_filtered, 9.0, 14.25)`。
- 实机使用当前零位、方向、限位和 IMU 外参；目标不匹配、反馈与时序处理沿用已经完成实测的固件。
- 主机读取状态超时不卸力，P4 本地运行到授权截止；固件自身故障处理仍保留。

这些描述是部署事实，不等于要求将整个固件反馈算法复制进新训练。训练侧新增 EMA、电压处理或延迟会改变基线配方，不能仅以“更接近实物”为理由自动加入。训练运行电压、BAM 供电和固件目标补偿的意义要分清，避免同一效果被重复计算。

## 4. 同步零位、HOME 与两类限位

[当前部署快照](deployment/D747A9-20261021.json)已由设备在线读回，并与 15 分钟试验前配置、固件默认关节夹具逐项核对一致。

必须区别以下两个范围，统一用 CAD 关节角度坐标表达：

| 范围 | 快照字段 | 意义 |
|---|---|---|
| 舵机目标指令范围 | `limits.per_joint[].servo_target_rad_range` | 将原生目标 20～1003 count 通过各关节零位、方向和 O0 仿射关系换算后的目标弧度范围 |
| 关节角度上下限 | `limits.per_joint[].joint_angle_rad_range` | 当前设备保存的关节运动角度范围，应与 CAD/实物机械范围核对 |

`saved_manual_count_range` 是当前 HOME/手动的编码约束，不是舵机完整目标指令范围。

- 当前固件策略输出按第一类范围截断；HOME/手动还遵守保存的逐关节限位。
- 训练中目标指令约束与关节机械约束必须分开，不能把所有策略目标先截断到关节机械限位，误改变基线控制行为。
- 如需表达已确定的实际指令边界，使用上述目标弧度范围，不因此引入 P04 原生 count 量化、观测器或故障链路。
- 训练的关节约束应核对 CAD 和实物，设备保存值不是已独立测得的全部硬限位。不要把部署零点直接写成 MuJoCo 的角度零位。
- 快照明确保存 15 关节顺序、14 个策略关节顺序、HOME 弧度与计算得到的 HOME 目标 count。嘴巴不占策略动作维度。
- 零位改变若使同一 CAD 角度对应不同的实际机械姿态，会影响策略；不能把任意 HOME 重定义当作无影响的坐标平移。

## 5. 必须修正躯干上部后背凸起的碰撞

实际机器人躯干上部后方的凸出外壳/平台会与地面接触，必须进入碰撞模型。当前 V2 资产的主板外壳有视觉网格，但 `cad_full_mainboard_1_visual` 的 `contype=0`、`conaffinity=0`，不会形成地面支撑；当前源码见 [robot.xml](../../src/mjlab_microduck/custom_v2/assets/robot.xml)。不能用“画面上看得到”代替接触动力学正确。

执行要求：

1. 对照真实 CAD 和装配，确定凸起外表面的尺寸、位置、朝向和所属刚体，补齐实际会触地的外壳碰撞。
2. 使用合理的基本几何体或多个凸体表示外形。不能用一个巨大凸包填掉真实空隙，制造额外支点。
3. 核对地面碰撞掩码、接触参数、摩擦和排除表；不要只改变视觉网格的颜色或分组。
4. 补碰撞时核对质量、质心和惯量，避免因为新增 geom 重复增加已包含在 CAD 惯量中的质量。
5. 训练、评估和部署仿真统一使用修正后的机器人资产；新资产另留身份，冻结旧训练来源不覆盖。
6. 做必要的重力沉降检查：仰卧、伏卧、侧卧及后背凸起可能支撑的坐姿。检查实际接触 geom、接触点、支撑力与关节姿态，不能允许外壳穿地而没有支撑。

MuJoCo 的碰撞掩码、网格凸化和惯量推断规则见[官方 XML 文档](https://mujoco.readthedocs.io/en/3.3.4/XMLreference.html)。这些是模型正确性检查，不是候选模型实验。

## 6. 在同一正式任务中训练后仰提前纠正

目标是**轻微后仰时就恢复平衡，而非允许倒下后再通过起身补救**。后背尚未触地时，缺失的后背碰撞不会直接提供纠正力，不能认为补碰撞就必然解决小幅后仰不响应。

在基线奖励结构上围绕这一目标作必要修改，并纳入同一任务、同一课程：

- 保留原有起身覆盖及前向平衡训练，增加站立附近前后倾斜与外力扰动，保证后向状态有足够训练覆盖。
- 同时覆盖缓慢后倾和动态后推；相同角度下不同角速度的恢复难度不同。
- 早期覆盖小幅、可恢复状态，再在同一课程中扩大扰动，避免只有严重倒地样本能获得有效训练。
- 检查站立奖励的姿态容差、阶段切换、动作变化惩罚和姿态锁定项，避免小幅后倾被当作无需纠正的“已站稳”。
- 奖励保持支撑、抑制继续倾倒以及恢复平衡。不得让“先倒地再起身”在站立抗扰任务中获得与未倒地恢复等价的成绩。
- 不预设必须由某个踝关节按固定方向动作，允许髋、膝、踝和头部协同；以机器人是否及时恢复为目标。
- 原始输出、部署过滤后的目标与实际响应是不同层。必要诊断记录观察→MLP→补偿/平滑/截断→舵机反馈，不能只凭外观静止断言 MLP 没有输出。

上述要求不是开展 P04/基线候选比较；新训练只走基线经验驱动的这一条路线。

## 7. 必要验证、最终验收与交付

不做候选实验，不做消融，不为验证理论上的“更真实”重复训练多条路线。

保留以下必要工作：

- 新资产碰撞/惯量检查，观测与动作接口检查，以及正式训练前的小规模启动检查。按仓库规则使用 64 环境、5 次更新检查训练能正常启动；它不是另一份候选策略。
- 一条正式训练任务，记录新随机种子、源码/资产身份、实际配方及 checkpoint。
- 最终模型评估按前后方向和扰动幅度分别报告。可采用 2°、5°、10° 等小角度档位作为明确检查场景；物理初始化须保持接触一致，不能简单转动机身后把脚穿入地面。
- 报告未倒地恢复、首次有效纠正时间、最大倾角、恢复时间、目标饱和及关节跟随情况。先倒下再起身记为站立抗扰失败；不得用起身成功率或连续运行时长掩盖它。
- 真机最终验收仍需操作者确认支撑并授权。后向保持改善不能以丢失前向平衡或原有起身能力为代价。

交付内容为：新训练配置和来源说明、修正后的碰撞资产与接触检查、正式训练记录、新 checkpoint 与包含归一化的 ONNX、部署契约/哈希，以及最终仿真和实际表现记录。

本文仅确定交接要求；目前没有执行这次新训练，也没有声称后背模型或后仰问题已经修复。
