# 冻结历史协议的外部执行器审核

本文件补充 `STRICT_3762_SINGLE_GPU.md`；不修改其中任何数值契约，也不改写已有资格检查所引用的协议哈希。

`run_chain.py`只等待已确认存活的资格进程。等待依据是PID和Linux进程启动tick，进程退出后必须重新核对十段各自smoke/batch报告的PASS及哈希，并验证真实第12次停止报告。不能仅凭等待结束、状态文件或日志猜测资格通过。

通过后依次调用`run_formal_phase.py --phase 0..9`；每段是独立进程，沿用原wrapper和已反向核对的argv，仅变更产物路径，首段复刻原SIGTERM停止事件。执行器没有任何奖励、课程、噪声、优化器或网络参数覆盖，也不使用资格权重。

正式入口再次核对文档/工具/配置哈希、数值源码和静态资源，检查该阶段新碰撞资格报告及原吞吐门槛；父权重限于本轮前一正式段已核验的产物。头部阶段保留原polish前提。每次分段完成核对实际run.json、源码、依赖、有效配置、checkpoint计数、控制步、CUDA RNG份数，以及原评测时点、两个种子、样本量和时长。评测结果不强制相同。

资格、正式训练共享排他进程锁。执行器另设链路锁，拒绝覆盖已有尝试；任一异常即停止，不自动重试或从段内续训。停止信号沿链路传至原训练器，让其保存原生checkpoint；不允许只终止外层后遗留训练进程并继续下一段。完成十段仅标记TRAINING_CHAIN_FINISHED_PENDING_FINAL_AUDIT，不能替代最终产物/行为审计或宣称目标已经完成。

审核发现并修正：首段原argv省略num-envs，资格边界工具必须显式追加64，不能假设该flag原已存在；正式argv仍保持省略并使用原默认8192。外层停止原先未转发到训练子进程，现已补齐信号转发与等待。CPU语法检查不等价于完整训练通过；实际运行证据另存qualification/formal。
