# 三版新碰撞步行策略：实机对比候选

用户授权推送多个模型，由用户进行实机比较。**优先试A（3500）**，B用于比较停止/保持，C观察继续训练后的变化；没有一版完成全部仿真或本轮实机验收。本次只交付文件，没有连接机器人、激活策略或启动动作。

三版均属于600.941825g、SC0090 v5、配对q/v误差、50Hz、新碰撞6804动力学谱系。**不是624.6g的新起身C版配方**，没有偷偷更换质量或惯量；当前起身模型保持不变。头部控制仍有缺口，本次统一使用头部/身体零命令比较步行；头部执行器仍属于14维策略输出，并非机械锁定。

## 共用运行契约

- 使用已有确认支持V2/SC0090的运行端；ONNX运行端导入表中ONNX，现有MDP上传入口使用对应`.mdp`。MDP为FP32 MDPOL001 v2、walking runtime `0x11D720E4`，不是旧alpha身份。不要只看同为61/14维就认定其他运行时兼容。
- 输入float32 `[1,61]`，输出`[1,14]`，50Hz，CAD HOME全0，action scale=1；归一化已内置，勿再次归一化。嘴部独立保持，不在14维输出内。
- 观测顺序：角速度3、重力方向3、HOME相对关节位置14、关节速度14、上一原始策略动作14、twist3、head4、body6。
- 输出顺序：left_hip_yaw, left_hip_roll, left_hip_pitch, left_knee, left_ankle, neck_pitch, head_pitch, head_yaw, head_roll, right_hip_yaw, right_hip_roll, right_hip_pitch, right_knee, right_ankle。
- 本次head四槽和body六槽都保持0，只改变twist。训练采用的非零头目标联合投影没有塞进MDP原生MLP；零请求投影仍为零，因此当前零头测试不需要额外适配。不能直接把本包当成非零头控接口验收。
- 训练未加动作EMA；对比时保持同一套已有实机滤波、电压补偿、零位、方向、目标限幅和反馈时序，记录实际配置，不为某版单独调整。ONNX中的通用stiffness/damping元数据不是SC0090固件P/D寄存器。

## 建议对比顺序

在同样的设备配置、地面和供电条件下逐一装入A/B/C并核对文件SHA。沿用现有手动初始化、使能和停止流程；本包不自动下发动作。

1. 零命令站立与停止保持，记录漂移、晃动和触限情况。
2. 前进0.2m/s后回零；稳定后再比较0.4m/s。另记录0.1m/s是否能起步。
3. 后退−0.2m/s、左右转±0.5rad/s，分别回零，记录实际响应与再次稳定所需时间。
4. 用相同动作顺序及试验时长比较，填写[结果模板](hardware-results-template.csv)，附视频/遥测、模型SHA、地面、电压和设备参数。出现异常时使用既有停止流程，保留失败记录。

## 软件交付验证

A/B/C分别以570/601/318组输入（含实际保存观测）核对原checkpoint与ONNX，最大绝对误差分别9.54e−7/9.54e−7/7.15e−7。MDP归一化系数与各层权重逐位一致，CRC、源ONNX SHA和V2 runtime已核验；未量化、重排输出、改归一化或伪造实机结果。

`manifest.json`列出全部文件SHA；`package_and_verify.py --verify-only`只读复验。`training-code.tar.gz`包含核对过哈希的代码/XML/JSON和依赖锁；完整网格及配对误差大数据未重复打包，身份记录在`source-archive.json`。模型资产对应此前已发布的[6804新碰撞包](../20261024-rise3762-collision-adaptation/README.md)。
