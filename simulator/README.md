# SC0090 本地交互模拟器

在浏览器里用键盘控制本仓库训练的行走和起身模型。三维机器人来自
[Pollen Robotics 官方 Microduck Sandbox](https://huggingface.co/spaces/pollen-robotics/microduck-simulator/tree/main)，
物理和策略由本地 Python 进程执行；不用启动训练，也不需要 CUDA GPU 执行演示。

## 启动

在 `microduck_rl` 根目录、已有 `uv sync` 创建的 Python 环境下：

```bash
# 首次安装前端依赖并构建，需要 Node.js 22.12+。
cd simulator/app
npm ci
npm run build
cd ../..

./scripts/play_sc0090_local.sh
```

打开 **http://127.0.0.1:8080/**。后续启动只需要最后一条命令。
如果没有构建产物，启动脚本会尝试用 `npm` 自动构建。
训练环境的完整安装方式见根目录 README；SC0090 工具依赖仍由根目录 `pyproject.toml` 管理。

训练机和浏览器在不同电脑时，在浏览器所在电脑建立端口转发：

```bash
ssh -L 8080:127.0.0.1:8080 <用户名>@<训练机地址>
```

然后打开自己电脑的 `http://127.0.0.1:8080/`。本地服务默认只监听回环地址。
也可以用 `--port 8090` 改端口；受控局域网可显式指定 `--host 0.0.0.0`。

## 操作

| 操作 | 按键 |
| --- | --- |
| 前进、后退 | W / S 或上下方向键 |
| 左转、右转 | A / D 或左右方向键 |
| 左移、右移 | Q / E |
| 清零行走指令 | Space |
| 重置为站立 | R |
| 坐姿、俯卧、仰卧、左侧卧、右侧卧 | 1 / 2 / 3 / 4 / 5 |
| 一次侧向扰动，速度增量 0.2 m/s | F |
| 暂停、继续物理仿真 | P |
| 旋转、缩放视角 | 鼠标拖动、滚轮 |

行走滑块设置 **指令速度**，界面另行显示仿真的实际速度。0.01–0.03 m/s 等极低速
可以用来检查策略是否真正移动；下发指令不代表已经达到该速度。
侧移上限 0.15 m/s，转向上限 1.0 rad/s。

自动模式在躯干低于 8 cm 或倾斜超过 45° 时进入起身；连续稳定站立 0.5 秒后切回行走。
稳定标准沿用 V3：高度至少 10.5 cm、倾斜不超过 20°、线速度小于 0.15 m/s、
角速度小于 1.5 rad/s、双脚接触地面。起身期间给起身模型的移动指令为零。
也可以选定单个模型，观察其独立表现。切换模型保留真实上一帧动作，重置才清除历史。

松开按键、窗口失焦或切到后台会清零指令。连接中断后，服务端至多 0.4 秒清零；
物理和站立控制继续运行。一次只接受一个活动窗口的控制，其他窗口可以观看。

## 自由探索与随机演示

点击页面的 **「开始探索」**，会随机编排行走、后退、侧移、原地转向、绕弯、低速前进、
停步和侧向扰动。每一轮把这些动作打乱后各演示一次，再生成下一轮；速度上限沿用控制台滑块。
探索会启用行走/起身自动切换，使用网页当前选中的两份 checkpoint。

每轮序列都自动混合行走与起身，并包含坐姿、俯卧、仰卧和左右侧卧，无需单独开启倒地选项。
页面明确显示「重置为……，等待模型起身」：这是设置测试初始状态，之后由策略自行起身；
它不表示机器人学会了主动躺下或坐下。起身与扰动后稳定期间不给行走指令，稳定站立后才继续。

- **序列编号**控制随机顺序和指令幅度。比较 checkpoint 时，先重置站立，使用相同编号、
  时长和速度设置。实际轨迹与耗时由各模型决定，途中意外跌倒会插入等待起身。
- **每段指令**默认为 4 秒，可调整到 2–10 秒；这是演示节奏，不改变策略频率或物理步长。
- **起身等待上限**默认为 12 秒，可调整到 2–60 秒。超时会记录失败、停止探索并暂停物理仿真，
  保留现场供检查；按 P 可继续，或手动重置。不会跳过失败自动开始下一段。
- 「停止探索」、方向键/Space、姿态按钮、切换控制模式或加载模型会退出探索。
  窗口失焦、切到后台或连接中断也会停止，不会自动恢复；旋转视角和调整速度滑块可以继续探索。
- 页面显示当前动作、经过的仿真时间和最近六段结果。指令段结束不代表速度跟踪合格；
  自由探索是交互演示，不代替定量评估，也不会修改或训练 checkpoint。

## 在网页选择 checkpoint

页面顶部可以分别选择 **行走 checkpoint** 和 **起身 checkpoint**，点击对应的「加载」。
列表显示训练版本、运行时间和轮次；两个任务分别加载，可以组合比较不同阶段的策略。
编号只表示该训练运行的编号，不能据此判断累计训练量或模型优劣。

- 默认附带本轮行走 V2、起身 V3 的 `model_5999`，新克隆仓库也能直接演示。
- 有本机训练日志时，自动发现 `logs/rsl_rl/` 下 SC0090 行走及起身各版本的 checkpoint；
  排除 smoke 测试和 source 副本。继续训练产生新文件后，点击「刷新列表」。
- 首次加载 `.pt` 时，在独立 CPU 进程中调用已有的归一化 ONNX 导出器，当前模型继续运行。
  导出结果缓存到 `simulator/models/cache/`，以后加载会校验并复用缓存，不占用训练 GPU。
- 导出与模型校验成功后才切换，并重置为站立；失败或导出超过 300 秒时保留原模型并提示错误。
  两类模型分开校验，不允许把起身 checkpoint 装到行走槽位。
- 网页选择只作用于当前演示进程。重启恢复 `models/manifest.json` 中的默认模型；
  要更改启动默认值，使用下面的命令行导出方式。

## 模型与计算一致性

`models/manifest.json` 记录当前两份 ONNX 的文件、SHA-256、来源 checkpoint、任务和导出提交。
启动时校验模型及 SC0090 参数的校验和。文件名带版本与内容摘要，加载后不会随着训练
自动变更；继续训练不改变已经运行的演示。

- 复用 `scripts/infer_policy.py` 的 61 维观测、14 维动作和 BAM 控制接口。
- SC0090 M6、12 V、固件 KP=20/KD=30、共享供电电阻 0.1 Ω、80 rpm 主动驱动限速。
- 策略 50 Hz；每次动作执行四个 5 ms 物理步；无动作低通、无额外动作限幅。
- 使用 groundcontact 模型，让身体落地接触有效；求解器和碰撞参数按训练配置设置。
- 浏览器只将 Python 返回的关节角和躯干姿态绘制出来，不做姿态插值或关节角裁剪。
- 只有仿真主线程读写 MuJoCo/BAM/ONNX。HTTP 线程通过有界队列提交输入，序号防乱序，
  独立时间戳处理断连；重置清除 BAM 电池、控制器、策略上一动作与稳定计时。
- checkpoint 导出使用独立进程和原子文件更新，模型切换由仿真主线程执行；校验源文件、
  导出文件、电机参数摘要，以及模型输入输出维度、关节顺序、动作缩放与有限数值。
- 无效动作或 MuJoCo 数值警告会暂停并显示错误，不自动重置掩盖失败。

这是固定标称参数的 **CPU MuJoCo 展示**，不是训练时包含随机化、传感器噪声和推搡的
批量评估。CPU MuJoCo 使用双精度状态，GPU Warp 使用单精度，不能把两者的轨迹当成逐位相同。
行走演示使用包含躯干接触的统一场景；原行走训练的模型主要保留脚部接触。它也不代替实机验证。

## 更改启动默认模型

从根目录使用统一导出入口，它调用本仓库已有的归一化 ONNX 导出器：

```bash
uv run simulator/scripts/export_models.py \
  --walk-checkpoint logs/rsl_rl/<行走运行>/model_5999.pt \
  --recovery-checkpoint logs/rsl_rl/<起身运行>/model_5999.pt
```

可以只提供其中一个 checkpoint，或通过 `--walk-task` / `--recovery-task` 指定兼容的任务。
导出使用现有训练环境，默认 `--device cuda:0`；本机驱动兼容路径需与训练时一致。
也可以显式指定 `--device cpu`。新 ONNX 先写入独立版本文件，再原子替换 manifest；重启演示后生效。
检查点编号是所属训练运行的编号，不是累计学习轮数。

临时演示其他已正确导出的模型：

```bash
./scripts/play_sc0090_local.sh --walking /path/walk.onnx --recovery /path/recovery.onnx
```

## 开发与验证

Python 服务保持运行，在另一个终端启动带 API 代理的前端开发服务器：

```bash
cd simulator/app
npm run dev
```

打开 `http://127.0.0.1:5173/`；修改前端后使用开发服务器，或重新 `npm run build`。

```bash
# 从仓库根目录运行
uv run --no-sync --with pytest pytest simulator/tests tests/test_infer_policy_bam.py -q
cd simulator/app && npm test && npm run build
```

Python 测试覆盖并发输入、断连、过期指令、状态清理、数值异常和实际 ONNX 的各姿态起身。
浏览器验证结果见 [VALIDATION.md](VALIDATION.md)。

`?official=1` 可打开保留的官方原版演示用于对照，它使用官方策略和浏览器内原版物理，
不是 SC0090 模型。原版有外部资源与联网功能，见 [上游说明](UPSTREAM_README.md)。
SC0090 入口的模型计算和三维资源都在本地，不调用原版多人联网或外部推理服务。

本目录与训练代码在同一个 Git 仓库；Node 依赖只位于 `simulator/app/node_modules`，
不参与训练模块导入。来源与上游更新方式见 [UPSTREAM.md](UPSTREAM.md)。
